# Architecture

## Layered design

```text
   Synthetic case authoring / sealed evaluator truth
                       |
          Evidence & disclosure registry
                       |
    +------------------+--------------------+
    | Agent runtime    | Human participant  |
    | LLM/Hermes/etc.  | web/CLI future     |
    +------------------+--------------------+
                       |
               typed action proposal
                       |
             Security and ACL gate   <-- NON-OVERRIDABLE
                       |
         Normative rule evaluator    <-- versioned jurisdiction pack
                       |
  strict: block | realistic: log + permit | experimental: controlled injection
                       |
       Actual event / state transition
                       |
            Append-only event log
                       |
           Findings and remedies
          / appeal / revision (future)
                       |
        Independent benchmark analysis
```

## Fundamental domains
- **Case truth:** evaluator-only facts; must not be sent to participants.
- **Actor perspective:** observed facts, independent memory, authorized disclosures, confidence and misunderstandings.
- **Evidence:** provenance, chain of custody, knowledge, disclosure, admission, fact-finding and review record are distinct states.
- **Normative model:** source-backed rule expectations and citations, with uncertain or disputed interpretation first-class.
- **Actual proceedings:** immutable recorded behavior; mistakes are neither erased nor automatically legalized.
- **Consequences:** objections, cure, forfeiture, harmless-error analysis, reversal, remittal, finality and retrial as jurisdiction-specific potential outcomes.

## State and event contracts
`Proposal` is an actor-attributed request. A fixed security layer rejects unauthorized operations in all modes. A rule evaluator returns findings without claiming to be a judicial decision. The engine determines allowed state transitions for the selected simulation mode and appends `TrialEvent` including accepted status, before/after phase and findings. An event can represent a rejected *attempt*; it must not be mistaken for an accepted act. Each rule and simulator version should be recorded for future replay/migrations.

### Implemented seams (Phase 1, offline)
- **`JurisdictionRuleset`** (`indubio.jurisdictions.base`): a protocol with frozen `RulesetMetadata` (id, version, validation status, optional effective date and sources) and `evaluate(RuleContext, action) -> list[RuleFinding]`. The ruleset receives a frozen snapshot and a copy of the action, may return *procedural* findings only, and never mutates state or decides acceptance. The engine resolves rulesets by `SimulationConfig.jurisdiction` and fails on unknown IDs rather than falling back. Events record `ruleset`, `ruleset_version` and `ruleset_validation`.
- The only registered pack is `de-criminal-demo-unvalidated` (`indubio.jurisdictions.demo`): the original schematic phase/motion checks, marked `unvalidated_demonstrator`, with no legal sources. It is **not** StPO procedure.
- The engine keeps actor authorization, evidence ACL and structural reference checks itself; they run before and independently of the ruleset in every mode.
- **Per-role action authorization** (`indubio.core.authorization`; demonstrator only, not StPO): one authoritative, read-only table maps each registered action model class to its allowed roles and denial rule ID. Every denial is a `security` finding, so it rejects in every mode, and no ruleset or setting relaxes it. Lookup is by exact class and fails closed: a canonical `Action` schema member without an entry (e.g. a new union member) is denied for every role with `AUTH_ACTION_UNREGISTERED`, as a normal rejected event that persists to and reloads from the SQLite journal. The table may only name members of `models.ACTION_TYPES` (derived from the `Action` union, checked at import), and a test asserts every member is registered.
  - **Typed journal contract at the proposal boundary:** before the ruleset runs or any event/state exists, `SimulationEngine.propose` refuses a runtime action whose exact class is not in `ACTION_TYPES` (a subclass of a registered model, a foreign object, `None`) with `TypeError`, and a schema-class action with out-of-schema values (e.g. built via `model_construct`) with `ValueError`. Such objects could otherwise be recorded as an unloadable payload, or serialize as their canonical base action and lose the real reason for denial on replay. The recorded proposal is the JSON-round-tripped, revalidated copy, i.e. exactly what the journal reloads.
  - `speak`, `submit_evidence`: judge, prosecutor, defense, defendant, witness (`AUTH_SPEAK`, `AUTH_SUBMIT_EVIDENCE`; submission still also requires evidence access, `ACL_EVIDENCE`). `move_phase`, `rule_on_motion`: judge (`AUTH_PHASE`, `AUTH_RULING`). `file_motion`, `object`: prosecutor, defense, defendant (`AUTH_MOTION`, `AUTH_OBJECTION`). `disclose_evidence`: judge, prosecutor, defense (`AUTH_DISCLOSE`); recipients judge, prosecutor, defense, defendant (`AUTH_DISCLOSE_RECIPIENT`).
  - **Passive observer:** `human_observer` holds a perspective but is authorized for no action kind and cannot receive disclosures. Intentional correction: before this table, `speak` and `submit_evidence` had no role check, so an observer could speak or submit granted evidence. All other permissions, rule IDs and descriptions are unchanged.
  - Order: the role finding comes first, then structural/ACL checks still run (e.g. `["AUTH_DISCLOSE_RECIPIENT", "ACL_EVIDENCE"]`), then ruleset procedural findings — the same order as before extraction. Disclosure grant revalidation (`derive_grants`) uses the same predicates as the engine.
- **`EvidenceRegistry`** (`indubio.evidence.registry`): immutable, deep-copied snapshot of `EvidenceRecord`s with actor-scoped views. `HIDDEN_TRUTH` records never appear in any view and are never submittable. When a registry is passed to the engine, the evidence ACL is derived from these scoped views; the legacy `available_evidence` mapping (ID grants without records) is still accepted, snapshotted and type-checked, but the two cannot be combined. The registry cannot be reinitialized, and the engine keeps its own snapshot so evidence views and the derived ACL always agree. Registry-wide iteration, `len`, `actor_ids()` and `snapshot()` are trusted setup APIs (iteration includes hidden-truth IDs); only `visible_to`/`accessible_ids` are actor-scoped.
- **Perspective projections** (`indubio.core.projection`, `SimulationEngine.perspective(actor_id)`): a deterministic, frozen, redacted view of the committed history for one known actor, derived only from engine-owned state (events, actor registry, evidence ACL, registry snapshot). It is a read-only view, never a source of legal decisions; `engine.events` and the SQLite journal stay the complete trusted audit history and are unchanged. Policy, conservative and fail-closed:
  - Unknown viewer → `PermissionError`; an event naming an unknown/inconsistent actor or a gapped/reordered history → `ValueError`, never a partial view.
  - Own events: full proposal (accepted or rejected); rule findings only on own *rejected* events, to explain the rejection.
  - Other actors' accepted events: author, role, phase change and action, by per-kind allowlist. A `SubmitEvidence` ID is shown only if the viewer may itself access that ID; otherwise the payload is withheld and `redacted_fields` says so. Unlisted action kinds are withheld from non-authors.
  - Other actors' rejected events: `withheld` — only the global sequence number and unchanged phase remain (author, kind, payload, findings hidden). The existence and position of a rejected attempt is therefore visible, as it is from sequence numbers.
  - Findings on accepted events (e.g. realistic-mode procedural findings) are evaluator/audit data and are not projected to any actor. Simulation mode, event metadata and `Actor.human_controlled` are not projected; ruleset ID, version and validation status are.
  - Projected evidence records omit `visible_to_actor_ids`; hidden truth never appears.
  - **Free-text trust boundary:** `Speak.text`, motion grounds, ruling reasons and objection grounds are untrusted actor-authored strings, passed through verbatim in public accepted events. Redaction is structural, not content-based; an actor who writes an ID or fact into public free text publishes it by its own act. Consumers must treat it as untrusted data.
  - **Legacy ID ACL boundary:** with the legacy `available_evidence` mapping there are no records; granted IDs are trusted caller-asserted setup input, projected as `accessible_evidence_ids` and used for redaction, with no record content and no epistemic-layer check. Use an `EvidenceRegistry` for sealed truth.
  - Not yet covered: confidential consultation channels, authenticated viewers (engine-state restoration from a journal: see below). `engine.evidence_view()` returns full `EvidenceRecord`s for the actor's *current* access (scenario-initial records, which still include `visible_to_actor_ids`, plus records received by accepted disclosure, returned with `visible_to_actor_ids` cleared so other holders are not revealed); it lists the same records as `perspective().evidence`. `engine.initial_evidence_view()` returns only the scenario-initial records. Projections use the narrower `ProjectedEvidence` (no visibility list, with `disclosed_at_sequence`).
- **Scenario manifests** (`indubio.scenarios`): `ScenarioManifest` (`schema_version: "indubio.scenario/1"`, `scenario_version`, `synthetic: true` required) declares synthetic actors and scenario-initial evidence (layer, per-actor visibility). Validation fails closed on unknown fields or schema versions, duplicate IDs, visibility naming unknown actors, and `hidden_truth` records that list any actor. `build_engine(manifest, mode)` builds the engine with an immutable registry; the ruleset ID must be registered. Bundled fixtures are loaded by allowlisted name. A manifest is trusted, author-written setup data, never actor input; it performs no network access. Real-case import is out of scope (see CASE_DATA.md).
- **Scenario provenance** (`indubio.core.provenance`): an engine built by `build_engine` stamps the same frozen `ScenarioProvenance` on every committed event, accepted or rejected (`TrialEvent.scenario`). It holds the author-declared identity (`scenario_schema_version`, `scenario_id`, `scenario_version`) and `setup_digest`, a SHA-256 over the canonical encoding (`setup_canonicalization: "indubio.scenario-setup/1"`) of the normalized setup the engine actually runs, computed by the engine from its private snapshots: jurisdiction (ruleset ID), actors sorted by ID (order not semantic), and every registry record including sealed truth in registry order (order semantic) with sorted visibility lists. Simulation mode, ruleset version, `title` and `disclaimer` are not part of the digest; mode and ruleset version are already in `metadata`. The encoding uses sorted keys, compact separators and ASCII escapes, so it does not depend on process or `PYTHONHASHSEED`; strings are not Unicode-normalized because IDs compare exactly. `provenance_schema`, `setup_canonicalization` and `setup_digest_algorithm` are literals, so a future encoding is an explicit new version. A consumer matching a journal against a scenario must compare every field. Callers pass a `ScenarioIdentity`, never a digest; an identity with a legacy bare-ID ACL is refused. Direct engines without an identity, and pre-provenance journal payloads, have `scenario=None`, and the field is omitted from their JSON, so their payloads keep their exact shape. **Privacy:** the digest is unsalted and covers sealed content, so it confirms guesses; it is trusted audit data and is never projected (projections carry no event `scenario` or `metadata`). Not covered: tamper evidence and signatures.
- **Engine restoration from a journal** (`indubio.scenarios.restore`): `restore_engine(manifest, events, mode=None)` and the read-only `restore_from_store(store, simulation_id, manifest, mode=None)` rebuild a fresh engine with `build_engine` and re-submit every recorded proposal through the ordinary `propose` path; no state is copied from the journal. Before an engine is returned, it checks (fail closed, `RestoreError`, no partial engine, no journal writes): items are exact `TrialEvent`s with sequences exactly `1..n` (and, from SQLite, row key = payload sequence); every event carries provenance equal to `manifest.provenance()` in every field; every event's `metadata` has exactly the engine's keys with the currently registered ruleset ID, version and validation status (no migrations); every event records the same valid `Mode` (a live `config.mode` change is not an event, so mixed-mode journals are refused; an explicit `mode` must match); and every regenerated event, rejected ones included, equals the recorded event. Phase, motions, disclosure grants, event-time projections and sequence numbering therefore come from the canonical transitions, and the restored engine continues with sequence `n + 1`. A journal with no provenance at all (pre-provenance payloads, direct engines) raises `LegacyJournalError` and remains loadable with `EventStore.load`; a journal mixing stamped and unstamped events is inconsistent. An empty history restores to `build_engine(manifest, mode or STRICT)` (an unknown simulation ID also loads as empty). Not covered: tamper evidence or authenticity (a consistent regenerable journal is trusted input), migrations, unrecorded `SimulationConfig` fields (defaults, as in `build_engine`), concurrent writers.
- **Opt-in speaking queue and floor** (`indubio.core.floor`, semantics `indubio.floor/1`; demonstrator only, not StPO/GVG): enabled only by `SimulationEngine(..., floor_rules=...)` / `build_engine(..., floor_rules="demo-floor-fifo-unvalidated")`, fixed at construction (not in the mutable `config`). Typed field-less actions `request_floor`, `withdraw_floor_request`, `release_floor` (prosecutor, defense, defendant, witness) and `advance_floor` (judge only); the observer has none. State is one holder plus a FIFO queue, each actor at most once. Accepted request appends; withdraw removes (order kept); release clears the holder only; advance ends the current holder and grants the queue head; an accepted `move_phase` that changes the phase clears holder and queue. Structural `security` findings in every mode: `FLOOR_DISABLED` (no floor control), `FLOOR_DUPLICATE_REQUEST`, `FLOOR_NOT_QUEUED`, `FLOOR_NOT_HOLDER`, `FLOOR_QUEUE_EMPTY`. Procedural findings come from the separate, versioned floor pack (`DEMO_FLOOR_SPEAK`: non-judge speech without the floor; `DEMO_FLOOR_FINISHED`: request/advance after finish), so strict rejects and realistic records the event without granting anything. The floor pack is separate so the default ruleset's identity and version (`0.2.0-demo`) and therefore every existing journal stay unchanged. Floor-enabled events add `floor_semantics`, `floor_rules`, `floor_rules_version`, `floor_rules_validation` to `metadata`; unscheduled events keep the original four keys. Floor events are public acts: accepted ones `public` to all, rejected ones `withheld`; `PerspectiveProjection.floor` (holder and queue, derived from the history alone and omitted without floor control) is reconstructible from the viewer's own projected events. Restoration requires the floor keys to be all-or-none and consistent across events, the registered floor pack's version (no migrations), and an explicit `floor_rules` to match; an empty history takes `floor_rules` from the caller. Not covered: interrupts, talk-over arbitration, time limits, scoring.
- **Evidence disclosure events** (`DiscloseEvidence`, policy in `indubio.core.disclosure`; demonstrator only, not StPO): one evidence ID to one recipient. Structural checks, `security` severity, in every mode: discloser role ∈ {judge, prosecutor, defense} (`AUTH_DISCLOSE`); recipient a known other actor (`REFERENCE_ACTOR`) with role ∈ {judge, prosecutor, defense, defendant} (`AUTH_DISCLOSE_RECIPIENT`); discloser currently holds the ID (`ACL_EVIDENCE`, same wording for unknown, sealed and inaccessible IDs, so no existence oracle); ID backed by a non-hidden record (`DISCLOSE_RECORD_REQUIRED`, i.e. legacy bare-ID grants cannot be disclosed). Timing is procedural (`DEMO_DISCLOSURE_PHASE` outside opening/evidence in ruleset `0.2.0-demo`): strict rejects; realistic records the event as accepted with the finding kept in the audit record. Only accepted events grant access; rejections never change visibility. Redundant disclosure is accepted as a no-op rather than revealing other holders. Grants are derived from the trusted history (journal round trips reproduce them) and revalidated during projection; an impossible accepted disclosure raises `ValueError`. Records themselves are never mutated.
  - Projection: discloser `own`; recipient of an accepted disclosure `recipient` (author, role, action); everyone else, and the named recipient of a rejected one, `withheld`. Received records carry `disclosed_at_sequence`.
  - **Event-time versus current visibility:** `accessible_evidence_ids`/`evidence` are current; per-event redaction uses access from strictly earlier events. A later disclosure never retroactively un-redacts an earlier `SubmitEvidence` event.

## Planned runtime adapters
- **Native LLM:** provider-agnostic structured outputs and model/version metadata, cost limits, schema validation, retries with bounded budgets.
- **Hermes Agent:** separate profiles / SOUL.md / memory backends; strict scoped capabilities, ephemeral credentials, least privilege and prompt-injection defenses.
- **Human:** same proposal contract, interactive private consultations, consent, suspend/exit and accessible controls.
- **Scripted:** deterministic fixtures used for CI and baseline tests.

Adapters never gain direct write access to the shared case database or private peer memory. The simulation scheduler supplies only allowed perspective and current legal context; a public transcript is not identical to every actor's full internal state.

## Persistence
SQLite append-only baseline. Later: immutable audit/hash chain, actor-private encrypted storage, transcript vs semantic event projections, replay with schema migrations and model provenance. The current starter does not provide cryptographic guarantees. Scenario journals can be restored deterministically (`indubio.scenarios.restore`, regenerate-and-compare against a matching manifest); legacy unstamped journals are load-only.

## Future UI and API
Optional FastAPI + WebSocket service with view permissions, synchronized live session, clear role switching and privacy-safe transcripts. Authentication, real-case data and deployment hardening must precede network exposure.
